# AI 英雄汇会议室预订系统：重建方案

日期：2026-09-29。依据：用户提供的三张现有系统照片和本次对话。

## 目标

同事在自己的电脑上查看、添加、修改和取消一间会议室的预约；Windows 平板持续展示最新状态。新系统从空白预约表开始，不迁移旧 EXE 的数据。

## 已确认的业务规则

- 房间名：AI 英雄汇；一间会议室、一台 Windows 平板。
- 部门共用一个预约密码，不要求每位同事注册。预约时填写预订人姓名。
- 允许使用第三方云服务；没有自管云服务器。
- 界面参考照片中的中英双语展示页、日程周视图与预订表单。
- 08:00–17:00 可预约；12:00–13:00 午休不可预约；30 分钟为最小时间单位。这些来自现有界面照片，作为首版规则。
- 会议室在重庆，预约与屏幕时钟按北京时间（Asia/Shanghai）。左侧卡片列出中国及马来西亚居林（吉打州）的公共假日，不把调休工作日当作假日。

## 架构

- 纯静态网页。电脑默认打开预订模式，Windows 平板打开 `?mode=display` 展示模式；同一份代码服务两种屏幕。
- GitHub 保存源码，静态站点可用 GitHub Pages 发布。GitHub Pages 的页面与免费账户所用仓库公开；代码中不放密码或管理员密钥。
- Supabase 托管用户认证与 PostgreSQL 预约表。管理员预建一个部门预约账号、一个只读平板账号；网页只含可公开的 publishable key。
- 数据库的排斥约束阻止重叠预约；行级安全规则限制角色。浏览器每 15 秒同步一次，同时在提交后立即刷新。轮询在网络断开时显示离线状态，恢复后重新加载。
- Supabase 尚未由用户创建。配置为空时启动明确标记的本机演示模式，便于检查界面；演示数据不表示跨设备同步。

## 用户流程

1. 同事打开同一个网页，输入部门共用密码，查看当日和本周空闲时段。
2. 输入会议名称、预订人、日期、开始/结束时间和可选备注，提交预约。冲突时显示可理解的提示。
3. 在预约列表或周视图打开会议，修改或取消。共用账号可以管理所有部门预约；填写的姓名只是展示信息，不能作为身份凭证。
4. 平板通过只读账号保持登录，显示当前空闲/占用、今天的会议、下一场会议、可用时段与周视图。平板数据随云端更新。

## 交付与验证

- 源码、数据库迁移 SQL、配置示例、部署步骤和自动化测试。
- 重点测试：午休与营业时间、30 分钟档位、相邻会议、时间冲突、取消后可重新预订、北京时间边界、跨设备刷新，以及假日数据排序与过滤。
- 本地预览检查桌面和 16:9 平板布局，以及预订/编辑/取消的完整演示流程。
- 实际云端与 GitHub 发布需要 Supabase 项目和 GitHub 登录；无凭据时仍完成可运行代码与本地验证。
